# 1.1 What LangGraph Actually Is (Mental Model)

### Introduction
Before writing graph code, you need a clear mental model. Most beginners assume LangGraph is "LangChain agents, but different." It is closer to a **state machine runtime** for LLM applications.

### Objective
Understand LangGraph's role as an orchestration runtime and why explicit graphs beat implicit `while` loops for agent control.

### Concept

LangGraph sits **on top of** LangChain and manages three things LangChain alone does not fully solve:

1. **Shared State** — A typed object passed between steps (not scattered local variables).
2. **Control Flow** — Fixed and conditional edges that define what runs next.
3. **Persistence** — Checkpoints that let you pause, resume, and replay conversations.

#### What LangGraph is NOT

| Misconception | Reality |
|---|---|
| A replacement for LangChain | LangGraph **uses** LangChain components inside nodes |
| A new LLM provider | It orchestrates existing models—you still use OpenAI, Azure, or Ollama |
| Magic autonomous AI | You define every node, edge, and routing rule explicitly |

#### Chains vs. Agent Loops vs. Graphs

| Pattern | Control Flow | State | Best For |
|---|---|---|---|
| **LCEL Chain** | Linear (`A \| B \| C`) | Stateless between calls | Pipelines, RAG, formatting |
| **Agent Loop** | Implicit (`while` until done) | Often hidden in executor | Quick prototypes |
| **LangGraph** | Explicit (nodes + edges) | Typed, inspectable, persistable | Production agents, multi-step workflows |

#### Core Vocabulary

- **State** — The data schema that flows through the graph (e.g., `messages`, `user_name`, `step_count`).
- **Node** — A Python function that reads state and returns a partial state update.
- **Edge** — A connection between nodes. Can be fixed (`always go here`) or conditional (`route based on state`).
- **Compile** — Converts your graph definition into a runnable application (`app = graph.compile()`).
- **Checkpoint** — A saved snapshot of state at a point in execution (enables memory and human-in-the-loop).

### Example

**The problem with an implicit agent loop:**

```python
while True:
    response = llm.invoke(messages)
    if response.tool_calls:
        result = run_tool(response.tool_calls)
        messages.append(result)
    else:
        break  # How many iterations? What if it never stops?
```

**The LangGraph mental model:**

```
START → agent → [tools | END]
              ↑__________|
         (bounded loop)
```

Every transition is declared. You can set a max iteration count, log each node, interrupt before tool execution, and resume later from a checkpoint.

**Minimal graph shape:**

```python
from langgraph.graph import StateGraph, START, END
from typing import TypedDict

class State(TypedDict):
    message: str

def greet(state: State) -> State:
    return {"message": f"Hello, {state['message']}!"}

graph = StateGraph(State)
graph.add_node("greet", greet)
graph.add_edge(START, "greet")
graph.add_edge("greet", END)

app = graph.compile()
app.invoke({"message": "LangGraph"})
```

No LLM required—the graph is just orchestration. The LLM becomes one node among many.

### 2 Use Cases
1. **Refund Approval Workflow:** An agent proposes a refund → graph pauses (`interrupt_before`) → human approves in a dashboard → graph resumes and executes the payment tool.
2. **Multi-Agent Research:** A supervisor node routes tasks to `researcher`, `writer`, and `reviewer` nodes—each a specialist with its own tools and prompts.

### Real-World RAG & Agentic Context
In **Real-World RAG**, the mental model shift is from "one retrieval chain" to "a graph that decides *how* to retrieve." A router node might send factual questions to vector search, keyword-heavy queries to BM25, and ambiguous queries to a rewrite-then-retrieve subgraph.

In **Agentic Systems**, this mental model prevents the most common production failures: runaway loops, untraceable decisions, and sessions that lose context on restart. When something goes wrong, you inspect the graph execution trace—not a pile of print statements in a `while` loop.

### Did you know?
LangGraph's `MessagesState` and `add_messages` reducer solve a problem every chatbot developer hits: appending messages without accidentally overwriting history. The reducer pattern is one of the most important design decisions you will make when defining graph state—and we cover it in Module 1.2.
