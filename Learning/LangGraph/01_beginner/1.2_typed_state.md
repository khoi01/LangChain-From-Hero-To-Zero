# 1.2 Typed State & Reducers

### Introduction
In Module 1.1 every field was a simple string or int—LangGraph **replaced** the value on each update. That breaks down quickly for chat history, logs, and counters. This module introduces **reducers**: rules that define *how* new values merge into existing state.

### Objective
Design typed state schemas with `Annotated` reducers so partial node updates behave predictably—especially when appending messages instead of overwriting them.

### Concept

#### Default behavior: last write wins

Without a reducer, returning a field from a node **replaces** the previous value:

```python
class State(TypedDict):
    items: list

# Node A returns {"items": ["a"]}
# Node B returns {"items": ["b"]}
# Final state: {"items": ["b"]}  ← "a" is lost!
```

For strings and flags, replacement is often what you want. For lists (messages, tool results, audit logs), it is usually wrong.

#### Reducers: custom merge logic

Attach a reducer with `Annotated[type, reducer_fn]`:

```python
from typing import Annotated

def append_list(existing: list, new: list) -> list:
    return existing + new

class State(TypedDict):
    items: Annotated[list, append_list]
```

When a node returns `{"items": ["b"]}`, LangGraph calls `append_list(current_items, ["b"])` instead of blind replacement.

#### Built-in: `add_messages`

The most common reducer in LangGraph apps:

```python
from typing import Annotated
from langgraph.graph.message import add_messages

class ChatState(TypedDict):
    messages: Annotated[list, add_messages]
```

`add_messages` knows how to merge LangChain message objects (`HumanMessage`, `AIMessage`, `ToolMessage`) and handles ID-based updates correctly.

#### Partial updates vs. full replacement

Nodes should return **only fields they change**:

```python
def my_node(state: ChatState) -> ChatState:
    return {"messages": [AIMessage(content="Hi")]}
    # Other fields in ChatState are untouched
```

The reducer runs only on fields present in the return value. Unmentioned fields keep their current values.

#### Why schema design matters early

State schema is your graph's **data contract**. Changing it later forces refactors across every node. Decide upfront:

| Field type | Typical reducer | Example |
|---|---|---|
| `str`, `bool` | none (replace) | `status`, `user_name` |
| `list` (append) | custom or `add_messages` | chat history, logs |
| `int` (accumulate) | `operator.add` | token counts, step counters |
| `dict` (merge) | custom merge fn | metadata bag |

### Example

```python
from typing import Annotated, TypedDict
from langchain_core.messages import HumanMessage, AIMessage
from langgraph.graph import StateGraph, START, END
from langgraph.graph.message import add_messages

class ChatState(TypedDict):
    messages: Annotated[list, add_messages]

def user_turn(state: ChatState) -> ChatState:
    return {"messages": [HumanMessage(content="Hello")]}

def assistant_turn(state: ChatState) -> ChatState:
    last = state["messages"][-1].content
    return {"messages": [AIMessage(content=f"You said: {last}")]}

graph = StateGraph(ChatState)
graph.add_node("user", user_turn)
graph.add_node("assistant", assistant_turn)
graph.add_edge(START, "user")
graph.add_edge("user", "assistant")
graph.add_edge("assistant", END)

app = graph.compile()
result = app.invoke({"messages": []})
# messages contains BOTH HumanMessage and AIMessage
```

### 2 Use Cases
1. **Chatbot history:** Each node appends user or assistant messages without wiping prior turns in the same run.
2. **Audit trail:** A `logs: Annotated[list, append_list]` field collects entries from every node for observability.

### Real-World RAG & Agentic Context
In **Real-World RAG**, graphs often accumulate context across steps: retrieved chunks, rewritten queries, intermediate summaries. Without reducers, a retrieve node followed by a rerank node might overwrite instead of append—silently dropping documents.

In **Agentic Systems**, tool results must append to message history so the LLM sees the full conversation including tool outputs. `add_messages` is the standard pattern used in ReAct graphs (Module 2.2).

### Did you know?
LangGraph also provides `MessagesState`—a pre-built `TypedDict` with `messages: Annotated[list, add_messages]` already defined. Many tutorials use it as a shortcut; defining your own schema gives you extra fields (e.g., `user_id`, `thread_id`) on the same state object.
