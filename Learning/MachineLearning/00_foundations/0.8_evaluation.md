# 0.8 Model Evaluation Fundamentals

### Introduction
"The model is 95% accurate" sounds impressive — until you learn that 95% of the records were negatives and the model simply predicts "no" every time. Evaluation is the skill of choosing a metric that measures what the **business** cares about, comparing against a sensible **baseline**, and ruling out **leakage**.

### Objective
Choose the right metric for regression and classification problems, always build a baseline first, and recognize the two silent killers of ML projects: data leakage and poor generalization.

---

### 🏆 The "Scorecard" Concept

#### 1. Always Start With a Baseline
Before any algorithm, ask: *what score does the dumbest possible model get?*
- **Regression:** predict the mean (or median) for every row.
- **Classification:** predict the majority class for every row.
- **Time series:** predict "same as last period".

If your fancy model does not clearly beat the baseline, you have learned something important — and saved weeks.

#### 2. Regression Metrics (how far off, on average?)

| Metric | Formula idea | Reads as | Use when |
| ------ | ------------ | -------- | -------- |
| **MAE** | mean(\|y − ŷ\|) | "off by $X on average" | you want robustness to outliers |
| **MSE / RMSE** | mean((y − ŷ)²), then √ | same units as target (RMSE) | large errors should hurt more |
| **R²** | 1 − SSE/SST | "% of variance explained", 1.0 is perfect | comparing models on the same data |
| **MAPE** | mean(\|y − ŷ\| / \|y\|) | "% error" | stakeholders think in percentages (beware y ≈ 0) |

#### 3. Classification Metrics (which mistakes matter?)
Start from the **confusion matrix**:

|  | Predicted positive | Predicted negative |
| --- | --- | --- |
| **Actually positive** | True Positive (TP) | False Negative (FN) — *missed it* |
| **Actually negative** | False Positive (FP) — *false alarm* | True Negative (TN) |

- **Accuracy** = (TP + TN) / all. Misleading on imbalanced data.
- **Precision** = TP / (TP + FP). *"When I flag something, how often am I right?"* Matters when false alarms are costly.
- **Recall** = TP / (TP + FN). *"Of all real positives, how many did I catch?"* Matters when missing a case is costly.
- **F1** = harmonic mean of precision and recall. One number when you need both.
- **ROC-AUC / PR-AUC:** threshold-independent summaries (Classification 2.5).

#### 4. Data Leakage (the silent killer)
Leakage = information from outside the training window sneaks into the features. Signs:
- A metric that is far better than the baseline *and* better than the domain expert thought possible.
- A feature that is a direct consequence of the target (`refund_issued` when predicting `complaint_valid`).
- Preprocessing fit on the whole dataset before the train/test split (see 0.6).

#### 5. Generalization vs. Memorization
A model is only as good as its **test** score on data that mirrors production. Training score tells you about capacity; test score tells you about usefulness.

### Example
```python
import numpy as np
from sklearn.datasets import make_classification
from sklearn.dummy import DummyClassifier
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import (accuracy_score, precision_score, recall_score,
                             f1_score, confusion_matrix, classification_report)
from sklearn.model_selection import train_test_split

# Imbalanced problem: only 5% of properties are overdue
X, y = make_classification(n_samples=5000, weights=[0.95, 0.05], random_state=0)
X_train, X_test, y_train, y_test = train_test_split(X, y, stratify=y, random_state=42)

# 1. BASELINE — always predict "not overdue"
baseline = DummyClassifier(strategy="most_frequent").fit(X_train, y_train)
print("Baseline accuracy:", accuracy_score(y_test, baseline.predict(X_test)))   # ≈ 0.95 (!)
print("Baseline recall:  ", recall_score(y_test, baseline.predict(X_test)))     # 0.00 — catches nothing

# 2. REAL MODEL
clf = LogisticRegression(max_iter=1000, class_weight="balanced").fit(X_train, y_train)
pred = clf.predict(X_test)

print(confusion_matrix(y_test, pred))
print(f"accuracy={accuracy_score(y_test, pred):.3f}  "
      f"precision={precision_score(y_test, pred):.3f}  "
      f"recall={recall_score(y_test, pred):.3f}  "
      f"f1={f1_score(y_test, pred):.3f}")
print(classification_report(y_test, pred))

# 3. REGRESSION METRICS, for reference
from sklearn.metrics import mean_absolute_error, mean_squared_error, r2_score
y_true = np.array([1000, 2000, 3000, 4000])
y_pred = np.array([1100, 1900, 3300, 3800])
print("MAE :", mean_absolute_error(y_true, y_pred))             # 200
print("RMSE:", np.sqrt(mean_squared_error(y_true, y_pred)))     # ≈ 212
print("R²  :", r2_score(y_true, y_pred))                        # ≈ 0.96
```

The baseline hits 95% accuracy while being useless. The real model may show *lower* accuracy but far higher recall — and recall is what the collections team actually needs.

### 2 Use Cases
1. **Overdue-tax prediction (recall-first):** Missing a property that will default costs real revenue; a false alarm costs one reminder letter. Optimize recall, accept lower precision, and report both.
2. **Automated complaint rejection (precision-first):** Auto-closing a complaint as "invalid" when it is real angers citizens. Here a false positive is expensive, so you require high precision and route uncertain cases to a human.

### Real-World Context
In **production ML**, the metric you optimize should be translated into money or time: "each percentage point of recall recovers roughly ₱2M in collections" is a sentence a CFO can act on. Model evaluation is also continuous — the same metrics are recomputed on live data to detect **model drift**.
In **LLM / RAG systems**, evaluation uses the same vocabulary: retrieval **recall@k** (did we fetch the right chunk?), answer **precision** (is everything in the answer supported?), and baselines like "no retrieval, just the LLM". Module 3.6 of the LangChain track is this lesson applied to RAG.

### Did you know?
Goodhart's Law — *"When a measure becomes a target, it ceases to be a good measure"* — is the reason data scientists report several metrics at once. A model tuned only for accuracy will happily sacrifice the rare class; a model tuned only for recall will flag everyone. The confusion matrix keeps you honest.
