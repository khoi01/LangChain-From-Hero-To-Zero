### Introduction
Four libraries do almost all of the heavy lifting in classical ML: **NumPy**, **Pandas**, **Matplotlib**, and **Seaborn**. Scikit-learn, XGBoost, and even PyTorch are built to accept their data structures. Learn these four well and every later notebook becomes readable.

### Objective
Know what each library is for, move data between them without friction, and recognize the handful of operations you will use in nearly every project.

---

### 🧰 The "Workshop" Concept
Think of your ML workbench as four tools:

#### 1. NumPy (The Raw Material)
- **What it is:** Fast N-dimensional arrays with vectorized math.
- **Why we need it:** Every model ultimately consumes a numeric matrix `X` of shape `(rows, features)`. NumPy *is* that matrix.
- **Key idea:** Never loop over rows in Python. `X * 2` multiplies a million numbers in C.

#### 2. Pandas (The Workbench)
- **What it is:** The `DataFrame` — a labeled table with column names, types, and missing-value handling.
- **Why we need it:** Real data arrives as CSVs, Excel sheets, and SQL tables with headers and gaps. Pandas lets you filter, join, group, and clean before converting to NumPy.
- **Key idea:** `df[["a", "b"]]` is a DataFrame; `df["a"]` is a Series; `df.values` is NumPy.

#### 3. Matplotlib (The Blueprint)
- **What it is:** The low-level plotting library.
- **Why we need it:** Residual plots, learning curves, and confusion matrices are how you *see* model behavior.

#### 4. Seaborn (The Finish)
- **What it is:** A high-level layer on Matplotlib for statistical plots.
- **Why we need it:** `sns.pairplot(df)` or `sns.heatmap(df.corr())` gives you a full EDA view in one line.

### Example
A typical "load → inspect → clean → split" flow that you will repeat in every exercise:

```python
import numpy as np
import pandas as pd
import matplotlib.pyplot as plt
import seaborn as sns

# 1. LOAD
df = pd.read_csv("Datasets/MachineLearning/sample/property_assessments.csv")

# 2. INSPECT
print(df.shape)              # (rows, columns)
print(df.dtypes)             # which columns are numeric / text
print(df.describe())         # mean, std, min, max per numeric column
print(df.isna().sum())       # missing values per column

# 3. CLEAN & TRANSFORM (vectorized — no Python loops)
df["age"] = 2026 - df["year_built"]
df["log_area"] = np.log1p(df["floor_area"])
df = df.dropna(subset=["tax_amount"])

# 4. GROUP & SUMMARIZE
by_district = df.groupby("district")["tax_amount"].agg(["mean", "count"])
print(by_district.sort_values("mean", ascending=False))

# 5. VISUALIZE
fig, ax = plt.subplots(1, 2, figsize=(10, 4))
sns.histplot(df["tax_amount"], ax=ax[0])
sns.scatterplot(data=df, x="floor_area", y="tax_amount", hue="district", ax=ax[1])
plt.tight_layout()

# 6. HAND OFF TO SCIKIT-LEARN
X = df[["floor_area", "age", "log_area"]].to_numpy()   # NumPy matrix (n, 3)
y = df["tax_amount"].to_numpy()                          # NumPy vector (n,)
```

The operations worth memorizing: `read_csv`, `shape`, `dtypes`, `describe`, `isna().sum()`, `groupby().agg()`, `merge`, `apply`, `to_numpy`.

### 2 Use Cases
1. **Joining municipal datasets:** `pd.merge(assessments, payments, on="property_id", how="left")` combines two systems into one modeling table and exposes properties with no payment record (`NaN`) — those are your overdue cases.
2. **Vectorized feature creation:** Computing `days_overdue = (today - due_date).dt.days` over two million rows takes milliseconds in Pandas and minutes in a Python loop.

### Real-World Context
In **production ML**, the Pandas code you write during exploration usually becomes the *feature pipeline* in deployment. Keep transformations as pure functions (`def add_features(df): ...`) so the same code runs in the notebook and in the API.
In **LangChain / RAG systems**, Pandas is how you prepare document metadata, evaluate retrieval results, and build the tables that `pandas` agents query. The `DataFrame` is the lingua franca between ML and LLM tooling.
