# 0.5 Data Understanding & Exploratory Data Analysis (EDA)

**Exercise:** [0.5_eda.ipynb](../../../Exercises/MachineLearning/00_foundations/0.5_eda.ipynb)

### Introduction
Every failed ML project has the same autopsy: someone trained a model on data they did not understand. **Exploratory Data Analysis** is the habit of looking before you model — distributions, relationships, gaps, and surprises.

A good EDA often answers the business question before any model is trained.

### Objective
Follow a repeatable EDA checklist, read the standard plots, and spot the data problems that would otherwise silently break your model.

---

### 🔍 The "Detective" Concept
Treat a new dataset like a crime scene: do not touch anything until you have surveyed it.

#### 1. Shape & Types (Who is in the room?)
- How many rows and columns? Which are numeric, categorical, dates, free text?
- Do the types match reality? (A `zip_code` stored as a number is a trap.)

#### 2. Distributions (What does "normal" look like?)
- **Numeric:** histogram or box plot. Is it skewed? Are there impossible values (negative area, year 1800)?
- **Categorical:** value counts. Are there 3 categories or 3,000? Any typos (`"North"`, `"north"`, `"N"`)?

#### 3. Missing Values (What is absent, and why?)
- Random gaps are a nuisance. Systematic gaps are a clue — maybe one district never records `year_built`.

#### 4. Relationships (Who is connected to whom?)
- Correlation heatmap for numeric features.
- Scatter plot of each promising feature against the target.
- Grouped means: `tax_amount` by `district`.

#### 5. Outliers & Leakage (What does not belong?)
- A single $50M property can dominate a regression.
- A column that is secretly the answer (`tax_paid` when predicting `tax_amount`) is **data leakage** — the model will look perfect and be useless.

### Example
A compact EDA pass that you can paste at the top of any notebook:

```python
import pandas as pd
import matplotlib.pyplot as plt
import seaborn as sns

df = pd.read_csv("Datasets/MachineLearning/sample/property_assessments.csv")

# 1. Shape & types
print(df.shape)
print(df.dtypes)
df.head()

# 2. Distributions
print(df.describe(include="all").T)          # numeric + categorical summary
df["district"].value_counts()                  # category balance

fig, ax = plt.subplots(1, 2, figsize=(10, 4))
sns.histplot(df["tax_amount"], bins=40, ax=ax[0]).set_title("Target distribution")
sns.boxplot(x=df["floor_area"], ax=ax[1]).set_title("Outliers in floor_area")

# 3. Missing values
missing = df.isna().mean().sort_values(ascending=False)
print(missing[missing > 0])                    # fraction missing per column

# 4. Relationships
numeric = df.select_dtypes("number")
plt.figure(figsize=(8, 6))
sns.heatmap(numeric.corr(), annot=True, fmt=".2f", cmap="coolwarm")

sns.scatterplot(data=df, x="floor_area", y="tax_amount", alpha=0.4)
df.groupby("district")["tax_amount"].median().sort_values().plot.barh()

# 5. Suspicious columns (possible leakage)
print(numeric.corr()["tax_amount"].sort_values(ascending=False).head())
# If something correlates at 0.99, ask: would I know this value at prediction time?
```

**Reading the output:**
- A right-skewed target (long tail of expensive properties) suggests predicting `log(tax_amount)` instead.
- A correlation near 1.0 between two *features* means they are redundant (multicollinearity).
- Categories with a handful of rows will need grouping into `"other"`.

### 2 Use Cases
1. **Finding dirty data before it costs you:** An EDA on building permits revealed that 8% of rows had `floor_area = 0` — a default from the legacy system. Without EDA, the model would have learned that zero-area buildings pay tax.
2. **Answering the question without a model:** Plotting complaint counts by district and month showed a single district accounting for 60% of flooding reports every July. The city reallocated drainage crews based on the chart alone.

### Real-World Context
In **production ML**, EDA becomes **data validation**: the same checks (ranges, missing rates, category sets) are automated and run on every new batch of data. If the distribution of `floor_area` suddenly shifts, that is **data drift** and your model may be stale.
In **LLM / RAG systems**, EDA means inspecting your document corpus: lengths, duplicates, languages, and empty pages. A RAG system over un-inspected PDFs inherits every scanning error.

### Did you know?
Francis Anscombe published four datasets in 1973 that have *identical* means, variances, correlations, and regression lines — yet look completely different when plotted. "Anscombe's Quartet" is the canonical argument that summary statistics without plots are not enough.
